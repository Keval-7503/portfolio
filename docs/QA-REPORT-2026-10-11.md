# Accessibility and performance report — 2026-10-11

## Environment

- Local production Cloudflare Worker at `http://127.0.0.1:8787`
- Lighthouse 12.8.2, headless Google Chrome, simulated mobile throttling
- Homepage measured after a warm-up request; contact form measured independently

## Results

| Route | Performance | Accessibility | Best practices | SEO | FCP | LCP | TBT | CLS |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `/` optimized | 92 | 100 | 100 | 92 | 2.1 s | 3.0 s | 10 ms | 0 |
| `/contact` | 96 | 100 | not run | not run | 2.0 s | 2.4 s | 30 ms | 0 |

The first homepage run scored 65 performance with a 10.5 s LCP. Lighthouse identified the 1.61 MB mascot PNG as avoidable image work. A responsive 700×727 WebP reduced the asset to 88.8 KB (94.5% smaller); the repeated run improved performance to 92 and LCP to 3.0 s.

## WCAG 2.2 AA review

Automated representative-route checks found no accessibility audit failures. Source and rendered-page review confirmed semantic landmarks/headings, a keyboard skip link, visible `:focus-visible` treatment, labelled form controls, polite status output, responsive reflow rules, and a `prefers-reduced-motion` override. No critical blocker was found.

Still required before a public launch: an owner-operated keyboard pass on desktop/mobile, 200% zoom/reflow review, actual screen-reader spot check, and confirmation that the externally rendered Turnstile challenge remains accessible with production keys.

## Performance interpretation

CLS and blocking time meet the target comfortably. Contact LCP meets the 2.5 s lab target; homepage LCP is 0.5 s above it under local simulated throttling, despite the strong 92 performance score. This local Worker uses a remote Neon database and is not a field/RUM result. Recheck from the deployed edge and collect p75 field data before claiming Core Web Vitals compliance.
